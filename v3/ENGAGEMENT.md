# Engagement iteration

Hypotheses, not measured results. Prioritize a fast, legible first interaction and an optional immersive room. The native work.html route is usable even when WebGL, CDN modules or assets fail. The primary CTA jumps directly to work when the room is interactive, otherwise opens the lightweight work page. Headphones are opt-in and navigation cancels pickup. Core scene becomes interactive before independent model and environment requests settle. Missing local GLBs do not retry ordinary 404s.

## Instrumentation
In-memory window.__portfolioFunnel entries and portfolio:milestone events record one event per milestone with milliseconds since navigation: room_script_started, room_interactive, room_first_render, walk_started, seated, workstation_reached, quick_work, room_explore, career_opened, resume_clicked, music_selected, headphones_started, headphones_completed, room_assets_settled. No analytics backend, persistence, cookies or visitor IDs. These are local diagnostic events only, not aggregate conversion data. If analytics is enabled later, measure landing-to-work, work-to-resume/contact, load failure, time-to-first-interaction, and by mobile vs desktop. Compare against a baseline before claiming any reduction in drop-off. Suggested usability targets: work accessible within one click, no forced animation, 2.5s LCP on representative mobile connection. Test actual browser interaction and device performance before production.
